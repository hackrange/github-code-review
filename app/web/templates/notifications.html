What gets sent

Only what is new. A finding that was here yesterday is not sent again, because a nightly message about the standing backlog is how people learn to filter the sender.

A message never carries the credential itself. It carries the same redacted preview the report files do, because a message lands somewhere with a different set of readers than this page has.

The digest describes the first few findings and then points here, which leaves the rest of a busy night unsaid. The attachment is every new finding in that scan, in the same columns as the vulnerabilities.csv this installation writes, so it opens in Excel and can be split across a team by somebody who has no account here. Never the standing backlog, and never on the three urgent kinds, which go out on their own and are easier to read as four lines of text.

Two things worth knowing before you turn it on. It carries more than the message body does, the matched line and the author's address as well as the masked preview, and it lands wherever mail lands. And it is a snapshot of one scan rather than the current list, so the file name carries the date and the page stays the thing to work from. Cells that a spreadsheet would otherwise run as a formula are escaped, because every value in it came out of a repository this tool does not control.

Azure setup
  1. Azure Portal, then App Registrations, then New Registration.
  2. Name it, for example Git Code Review Email, and register it.
  3. Copy the Application (client) ID and the Directory (tenant) ID.
  4. Certificates & Secrets, then New Client Secret, and copy the Value.
  5. API Permissions, then Add a permission, then Microsoft Graph, then Application permissions.
  6. Add Mail.Send, then Grant admin consent.
Application permissions rather than delegated: nobody is signing in, so there is no user to delegate from. Without the admin consent step the permission is listed and does nothing.
Organizations without a connection

A fine grained token reaches one organization, so each one needs its own connection, and nothing says so when a new one appears. This asks the GitHub tokens you already have which organizations their account belongs to and compares that with the connections. It also names a connection that is limited to an organization its token cannot reach, and a token whose resource owner is the account rather than an organization. Both of those sign in fine and scan nothing. It only sends when it finds something.
