Connecting Bitbucket Cloud

Access tokens, workspaces, and what changed in 2026.
Back to connections
App passwords are gone. Atlassian stopped new ones on 9 September 2025, ran brownouts from 9 June 2026, and removed them entirely on 28 July 2026. Anything still using one has already stopped working. Use an access token or an API token.

Which token

KindReachesUse it when
Workspace access token Every repository in the workspace, and can list the workspace itself The normal choice. One connection per workspace.
Project access tokenOne project's repositories Scanning part of a workspace.
Repository access tokenOne repository A single repository.
API tokenWhatever the account can see Tied to a person rather than a workspace.

Scope: repository:read. Nothing needs write. Workspace settings → Access tokens, or Repository settings → Access tokens.

Filling in the connection

  • Addresses — leave them. Bitbucket Cloud is https://api.bitbucket.org/2.0 for everybody, and they are filled in for you.
  • Workspace — the slug out of the URL (bitbucket.org/acme/repo). A project or repository token cannot list workspaces, so name it here for those. A workspace token finds its own, and you can leave it empty.
  • Token — the access token itself. Encrypted here, never written to a file.

What is not available

Bitbucket has no equivalent of Dependabot alerts, code scanning or secret scanning alerts, and no API for two step status, so those are skipped rather than called and read as empty. Pull request history is not wired up yet either.

What runs, which is nearly all of it: secrets across the full history, code analysis, SBOM and dependency vulnerabilities, triage, exceptions and both report files.

Bitbucket Data Center is a different API from Bitbucket Cloud and is not supported here.
