{# One mapping from a sign off state to what the page says about it, used by both tables here. Two copies of it is how the card and the column end up disagreeing the first time somebody edits one of them. `beside_branch` picks the longer wording, for the badge that sits next to a branch name rather than under a column headed State: "expired" on its own there reads as a fact about the branch rather than about a review of it. The green one says "certified" in both places. It used to say "current" under the State column, which is a step removed from the question anybody is actually asking of that page, and it left the reader to work out current what. The rest of the set still reads as states beside it: certified, needs re-checking, expired, withdrawn, not applicable. #} {% macro cert_badge(state, why, beside_branch=False) -%} {%- if state == 'active' -%} certified {%- elif state == 'stale' -%} needs re-checking {#- Gray, and no call to action. A scan signed this and a scan will sign it again; asking a person to re-check something no person ever checked is work invented out of nothing, and it buries the amber ones that mean it. -#} {%- elif state == 'rescanning' -%} waiting for the next scan {#- Gray, and no call to action. The branch this names is not one the last scan found, so there is no diff to send anybody to look at: the compare link would point at commits the host has collected and return a 404. Saying "needs re-checking" here asks for work that cannot be done. -#} {%- elif state == 'unknown' -%} branch not found {%- elif state == 'lapsed' -%} {{ 'certification expired' if beside_branch else 'expired' }} {%- elif state == 'revoked' -%} {{ 'certification withdrawn' if beside_branch else 'withdrawn' }} {#- Gray, and worded as a statement about the branch rather than about anybody having read it. Nothing here is a sign off. -#} {%- elif state == 'not_applicable' -%} not applicable {%- else -%} {{ state }} {%- endif -%} {%- endmacro %}
