Pointing an editor at this

One language server answers all of them, so the setup is the same three things everywhere: the address, your token, and whether to look at the whole file or only what you changed.

The address is {{ api_url }}. That is what this page was reached on, so if it works in your browser it works from your editor on this network.

Check it first, before touching any editor. If this does not answer, nothing else will:

curl -H "Authorization: Bearer <your token>" \
     {{ api_url }}/ping

Visual Studio Code

Install the Git Code Review extension, then in settings.json:

"gitCodeReview.server": "{{ api_url }}",
"gitCodeReview.token": "<your token>",
"gitCodeReview.reviewOn": "save",
"gitCodeReview.changedLinesOnly": true

Keep changedLinesOnly on. A repository with two thousand findings in it will show you two thousand findings, and none of them are yours.

JetBrains, IntelliJ and the rest

Settings, then Tools, then Git Code Review. Same address, same token. The plugin registers itself as an LSP client, so nothing else is needed.

Eclipse

Eclipse speaks LSP through LSP4E rather than a plugin of its own. Install LSP4E from the marketplace, then add a server with the address above and the token as a header.

Neovim, Helix, Sublime and anything else

Any client that speaks the Language Server Protocol works. Point it at the address, send the token as an Authorization header, and it will behave like any other language server.

Before a commit, and in a pipeline

An editor is not the only place this is useful, and a hook needs no token at all because it runs where the code already is:

ghscan review . --diff HEAD --fail-on secrets

Exit 3 means it found something. That is the only place a credential can still be stopped rather than rotated.

A token is you, with less of you. It goes in your editor's settings, which is a file that ends up in backups and sometimes in a repository. Give it the shortest expiry you can live with, and delete it here the moment you stop using that machine.
