Cursor installs the same file. It is a fork of Visual Studio Code and takes the same package; there is no separate download and no separate plugin to keep in step.

Installing it

  1. Command palette, then Extensions: Install from VSIX, and pick the file you just downloaded. Or from a terminal: 
    code --install-extension {{ packages.vsix.name if packages.vsix else 'git-code-review.vsix' }}
cursor --install-extension {{ packages.vsix.name if packages.vsix else 'git-code-review.vsix' }}
  2. Command palette, then Git Code Review: Set the token. It is kept in the editor's secret storage rather than in a settings file that ends up in backups and sometimes in a repository.
  3. In settings.json: 
    "gitCodeReview.server": "{{ api_url }}",
"gitCodeReview.reviewOn": "save",
"gitCodeReview.changedLinesOnly": true
  4. Command palette, then Git Code Review: Check the connection. It says what is wrong, if anything is.

Keep changedLinesOnly on. A repository with two thousand findings in it will show you two thousand findings, and none of them are yours.

JetBrains: IntelliJ, PyCharm, GoLand, WebStorm, Rider
{% if packages.lsp %}

Download {{ packages.lsp.name }} {{ packages.lsp.kilobytes }} KB. Needs Node 18 or newer, and nothing else: there is nothing to install.

{% endif %}
  1. Unpack it somewhere that will stay put, such as your home directory.
  2. In the IDE, install LSP4IJ from the JetBrains Marketplace. It is free, it works in the Community editions, and it is what lets an IDE run a language server it was not built with.
  3. Settings, Languages & Frameworks, Language Servers, then add a user defined server: 
    Name:     Git Code Review
Command:  node /path/to/{{ lsp_root }}/server/main.js
Env:      GCR_SERVER={{ api_url }}
          GCR_TOKEN=<your token>
  4. Under Mappings, give it the file name pattern *, or just the languages you care about.

The token goes in the run configuration for that server, which is a file on your machine. Give it the shortest expiry you can live with.

LSP4IJ is the one piece here that does not come from this server: it is a JetBrains Marketplace plugin and we cannot hand it out. On a machine with no way out to the internet, download it once from a machine that has one and install it from disk.

Eclipse

Eclipse speaks this through LSP4E rather than a plugin of its own. That is not a shortcut: LSP4E is the Eclipse Foundation's own language server client, and a plugin of ours would be a wrapper around it.

  1. Download and unpack the language server above.
  2. Help, Eclipse Marketplace, install LSP4E.
  3. Preferences, Language Servers, add a server: 
    Command:  node /path/to/{{ lsp_root }}/server/main.js
Env:      GCR_SERVER={{ api_url }}
          GCR_TOKEN=<your token>
  4. Associate it with the content types you want reviewed, on the same page.

LSP4E comes from the Eclipse Marketplace rather than from here, for the same reason. On a machine with no way out, fetch it once elsewhere and install it from the archive.

Neovim, Helix, Sublime Text, and anything else

Any client that speaks the Language Server Protocol runs the same server. Point it at node /path/to/{{ lsp_root }}/server/main.js with GCR_SERVER and GCR_TOKEN in its environment, and it behaves like any other language server. The README in the package has the rest of the settings.

What it does, and what it does not

Open or save a file and its text is sent to {{ api_url }}/review. It is written to a temporary directory there, read by the same engines a scan uses, graded by the same triage, and deleted. Nothing is stored. A review creates no finding, no exception and no scan, which is why it is safe to run on every save and why a stolen token cannot change anything here.

It does not scan your repository. That is the nightly job, and an editor showing a repository's whole backlog is an editor somebody turns off by Friday. By default only the lines you changed against HEAD carry findings, and the status bar says how many older ones are in the file.

A credential is shown in red whatever its severity, because a live key in a file you are about to commit is the one thing here that cannot wait for a review. Anything the triage set aside is shown struck through rather than hidden, so you can disagree with it.

Before the commit, and in the build

An editor is not the only place this is useful, and a hook needs no token at all because it runs where the code already is:

ghscan review . --diff HEAD --fail-on secrets

Exit 3 means it found something. That is the only point where a credential can still be stopped rather than rotated.
