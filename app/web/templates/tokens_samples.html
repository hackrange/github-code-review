Ready-made scripts that let a build pipeline ask this server what needs fixing before code ships. They tell whoever runs the pipeline:

  • Secrets in the code, and that each one has to be rotated first.
  • Packages to upgrade, with the exact version to move to.
  • Container images to rebuild, when the base image is out of date.
  • Problems in build and CI files, such as GitHub Actions workflows and Dockerfiles.
  • Code fixes, only for findings an AI review has already read.

They can also stop a deploy when something serious is found, attach an SBOM to a release, and warn before a token expires.

Getting started in GitHub Actions, in three steps

1. Make a token. On the Tokens tab, tick only reports, give it a name such as payments pipeline, and copy it.

2. Store it in GitHub, never in a file. In your repository open Settings > Secrets and variables > Actions:

  • under Secrets, add GCR_TOKEN holding the token
  • under Variables, add GCR_URL holding {{ api_url }}

3. Add the files. Copy the kit's bash and python folders to .github/gcr/, and a workflow from github-actions/ to .github/workflows/. Push, and open the Actions tab to see the result.

If the run says HTTP 403: refused before the API, the runner's IP address is not allowed through to this server. Ask an administrator to allow it, or use a self-hosted runner inside your network. The guide's FAQ covers this and every other message.
