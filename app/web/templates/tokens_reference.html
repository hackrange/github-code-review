Using the API OpenAPI (Swagger) JSON Postman collection

Every call goes to {{ api_url }} with the token in a header: Authorization: Bearer <token>. Each answer holds only what the token's owner can open in this web app. A repository you cannot see answers 404, the same as one that does not exist.

The reports scope covers findings, SBOMs, trends, exceptions and the deploy check. The OpenAPI file opens in Swagger UI, Insomnia and most code generators. In Postman, import the collection and put your token in its token variable.

Checking before a deploy

The deploy check answers pass, fail or unknown for one repository and branch. unknown means that branch was never scanned, so treat it as a stop, not a pass. A script like this stops a deploy when there is something to fix:

#!/usr/bin/env bash
# Stops the deploy when the last scan found something to fix.
set -euo pipefail
GCR="{{ api_url }}"
REPO="acme/payments"     # org/name
BRANCH="main"

answer=$(curl -fsS -G "$GCR/check" \
  -H "Authorization: Bearer $GCR_TOKEN" \
  --data-urlencode "repo=$REPO" \
  --data-urlencode "branch=$BRANCH" \
  --data-urlencode "fail_on=high")

verdict=$(jq -r .verdict <<<"$answer")
jq -r .message <<<"$answer"
jq -r '.blocking[] | "  [\(.severity)] \(.area): \(.title) \(.file)\n    \(.fix // .link)"' <<<"$answer"

[ "$verdict" = "pass" ] || exit 1

It answers from the last scan, and says when that was in last_scanned_at. For code that has not been scanned yet, such as a pull request, use the pull request gate.
