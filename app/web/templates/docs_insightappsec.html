Setting up Rapid7 InsightAppSec

Start InsightAppSec scans from External sites and read the findings back. Step by step, from nothing.
Back to Integrations
How it fits together. InsightAppSec never scans a bare address. Every scan runs from a scan config that lives in InsightAppSec. The config holds the start address, what to attack with, which engine runs it and how to sign in. This product only says which config to run for each site. It then follows the scan and brings the findings back to the site's page. So most of the setup happens in Rapid7, and only the last two steps happen here.

Before you start

  • An InsightAppSec subscription. A trial account can only read through the API, so it cannot start scans.
  • Somebody who is a platform administrator in the Insight platform, or who can make users and give them InsightAppSec roles.
  • External sites switched on here, on the Web and external sites tab. InsightAppSec scans start from a site's page.
  • The sites you want to scan, added under External sites.
  • Permission to scan them. InsightAppSec sends real attack payloads from Rapid7's engines.

Step 1. Find your region

Every Insight account is hosted in one region, and the API answers at that region's own address. The wrong region gives a refused key or a sign in page.

  1. Sign in to InsightAppSec and look at the address bar. The first part of the host is the region. https://us2.appsec.insight.rapid7.com means us2.
  2. In the United States you can also check Administration > Company Settings > Organization Settings. The Data Storage Region says United States 1, 2 or 3.

Do not go by "the first two letters". That old advice is wrong for us2, us3, me1 and aps2.

Step 2. Make an account for this integration

The key you make in step 4 acts as the user who made it, with that user's rights at the moment of each call. Use an account made for this job, not a person's own. That way the scans it starts are logged under a name everybody recognizes, and nothing breaks when somebody leaves.

  1. In the Insight platform, go to Administration > User Management and create a user. A shared mailbox address works for the email.
  2. Give it the Application Security product.
  3. Give it a role that can read apps, scan configs and vulnerabilities, and that can start and stop scans. Either of these works:
    • Read Write. Rapid7's API reference lists Manage Scans and Manage Vulnerabilities for it, which covers everything here.
    • Scan Manager, the smaller choice. It can start scans and change scan configs, but not edit apps. Rapid7's two RBAC pages disagree on whether it can see vulnerabilities. If findings never come back, this is why, and Read Write fixes it.

Could you use an organization key instead? You can. Only a platform administrator can make one, it is not tied to a person, and it reaches every app. The catch is that Rapid7 describes it as a super key that can do anything in every Rapid7 product you have, not only InsightAppSec. A user key with one role is the safer choice.

Step 3. Let the account see the apps

A user who is not a platform administrator only sees the apps it was given. The key can only scan what the account can see.

  1. In InsightAppSec, open each app you want to scan from here.
  2. Go to Manage App > Manage Users and add the account. A user group that holds the account works too, and it is easier when there are many apps.

You can skip this step with an organization key.

Step 4. Make the API key

  1. Sign in to the Insight platform as the account from step 2. A user key always belongs to the person who makes it. Nobody can make one for somebody else.
  2. Go to Administration > User API Keys, then press Generate New User Key.
  3. Pick the organization, give the key a name such as "Git Code Review", and press Save.
  4. Copy the key now. Rapid7 shows it once and never again. If it is lost, delete it and make another.

For an organization key, a platform administrator uses Administration > Administrator API Keys > Generate New Organization Key instead. Older Rapid7 pages show a gear icon and an API Keys page, which is the same thing in an older layout.

Step 5. Put each site on the Targets allowlist

InsightAppSec only scans domains on its Targets allowlist. A scan config whose addresses are not on it fails, and Rapid7 reports that under the confusing name LICENSE_INVALID.

  1. In InsightAppSec, go to Targets and press Add Targets.
  2. Type one domain per line, such as shop.example.com. Rapid7 drops any protocol or path you type. *.example.com covers every host under it.
  3. Make sure each target is enabled. New ones are.

A target that has been scanned can be turned off but never deleted.

Step 6. Make an app and a scan config for each site

  1. Go to Apps > Add App. Give it a name, its target addresses and the users from step 3.
  2. In the app, add a scan config. Give it a name people will recognize here, because this product lists configs as "app: config".
  3. Set the start address (Rapid7 calls it the seed URL) to the site's own address, such as https://shop.example.com/. This product reads the start addresses and offers the config first on the page of the site it starts on.
  4. Pick an attack template:
    • Crawl Only for the first run. It sends no attacks, and it shows whether the engine can reach the site and sign in.
    • OWASP 2021, SQL Injection and XSS or another focused template for regular scans.
    • All Modules only on test and staging sites. Rapid7 warns it can slow down or disrupt a site customers use.
  5. Pick the engine. Cloud reaches sites on the internet. A site only reachable inside the network needs an on premises engine (see step 8).
  6. Save, and fix anything the config says is wrong. A config with errors fails every scan. This product marks such configs "has errors" in its list.

Step 7. Set up sign in, if the site has one

The sign in for an InsightAppSec scan lives in its scan config. The sign in saved on a site here is not sent to Rapid7. In the scan config, under Authentication, pick one of these:

  • Automated login: a user name and password with the login page. Check it with the AppSec Chrome extension.
  • Macro, Selenium or Traffic: a recording of the sign in (.rec, .side, or .har and similar).
  • HTTP Basic, NTLM or Kerberos, a client certificate, or OAuth 2.0.
  • Session hijacking: paste a signed in cookie. It stops working when that session ends.

Also set the logged out detection so the engine knows when it has been signed out and signs in again.

Avoid multi factor sign in for scans started from here. It makes every scan stop at "Awaiting Authentication" until a person signs in through the Rapid7 extension. Rapid7 suggests turning MFA off for the scan account, or using bootstrap authentication.

Step 8. Let Rapid7's engines through the firewall

A web application firewall such as Cloudflare often blocks attack traffic, and the scan then finds nothing or fails. Allow the cloud engine addresses for your region. Rapid7 publishes two lists that do not agree, so allowing both is the safe choice.

Internal sites need an on premises engine, installed inside the network. It runs on Windows (10, 11, or Server 2016 to 2022) with .NET 4.8, about 8 GB of memory, 4 cores and 100 GB of disk. It only connects out, to https://<region>.appsec.insight.rapid7.com and https://<region>.engines.appsec.insight.rapid7.com. Set it up under Administration > Application Security Settings > Manage on-premises engines, then pick its engine group in the scan config.

Step 9. Connect it here

This server has to be able to reach https://<region>.api.insight.rapid7.com on port 443.

  1. Open Settings > Integrations.
  2. Pick the Region from step 1 and paste the API key from step 4.
  3. Press Test the connection. It reads only, and it uses the key you typed even before it is saved. It says how many apps and scan configs the key can see. "Can see no apps" means step 3 is not done.
  4. Set Scans at once to fit your license and engines. A start past it is refused, so nobody queues twenty scans on one engine by mistake.
  5. Tick Turn on InsightAppSec scans and press Save.
  6. Press Refresh scan configs. This reads every app and scan config the key can see, with their start addresses. Press it again whenever somebody adds a config in Rapid7.

Step 10. Run the first scan

  1. Open the site under External sites and press Run a scan.
  2. Under Run it on, pick Rapid7 InsightAppSec.
  3. Pick the scan config. The ones that start on this site are listed first and marked "starts on this host". The one you pick is remembered for the site.
  4. Tick the box confirming you may scan the site, and press Start.

A Crawl Only config is a good first run. When it completes with no errors, switch the site to a config with a real attack template.

While it runs

This product checks the scan every 3 minutes and shows its status on the scan page. It stops checking when the scan reaches COMPLETE or FAILED, which are the only two end states. If neither comes in 72 hours, the scan is marked failed here. It may still be running in Rapid7.

StatusWhat it means
PENDING, QUEUED, PROVISIONINGWaiting for an engine. A second scan waits while the first runs.
RUNNINGThe engine is crawling and attacking the site.
SCANNED, PROCESSEDDone scanning. Rapid7 is processing the results. Findings come in at COMPLETE.
PAUSEDPaused in Rapid7. It is stopped after 24 hours paused (4 in Europe).
BLACKED_OUTInside a blackout window set in Rapid7. It carries on when the window ends.
AWAITING_AUTHENTICATIONA person has to sign in for it in Rapid7. See step 7.
COMPLETEFinished. The findings are read and added to the site.
FAILEDIt could not finish. The reason is shown on the scan page.

Stop on the scan page asks Rapid7 to stop the scan and keep what it found so far. Those findings come in when Rapid7 finishes stopping it.

What comes back

  • Each InsightAppSec vulnerability becomes a finding on the scan. It shows the attack module's name and the parameter, the address, the request method, Rapid7's evidence and recommendation, the CWE where Rapid7 gives one, and the CVSS vector and score.
  • Severity follows Rapid7. Critical, High, Medium and Low are the same. Informational and the old Safe level both become info.
  • Each finding links to the same finding in InsightAppSec, and the scan links to the scan. Opening them needs a Rapid7 sign in.
  • Rapid7's review status (unreviewed, verified, false positive, ignored) shows beside each finding. A false positive marked in Rapid7 is still counted here until somebody marks it here too, because the two products keep their own decisions.
  • False positive, severity and exception decisions made here carry into the next scan of the same site, the same as for any other scan.
  • A completed scan counts as a dynamic test of the web applications behind the site, on the Web Applications tab under Blast Radius.

When something goes wrong

You seeWhat to do
The API key was refusedThe key was copied short, was deleted, or belongs to another region's organization. Check the region first.
The key is not allowed to do thatThe account's role is too small. Use Read Write, or check step 2.
Can see no appsGive the account access to the apps (step 3).
Answered with a web page, or a redirectThe region is wrong, or a proxy is in the way.
An address is not on the Targets allowlist (LICENSE_INVALID)A start or scope address in the config is not an allowed target. Add it (step 5).
The scan config is not validOpen the config in Rapid7 and fix what it lists. Usually an address.
The sign in did not work (BAD_AUTH)Record the sign in again, or check the password in the config (step 7).
The site did not answer the engineThe site is down, or a firewall blocks the engines (step 8).
No engine was availableThe on premises engine is offline. Check it in Rapid7.
Rapid7 is limiting requestsNothing. Checking stops until Rapid7's limit resets, then carries on.
Complete with no findings, and none expected to be missingCheck the role can read vulnerabilities (step 2), and that the engines got past the firewall.

When you ask Rapid7 support for help, give them the "Rapid7 reference" shown with the error. It is their correlation id for that request.
